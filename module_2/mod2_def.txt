1. Child process-fork()
->	A new process created by another process is called a child process.
->	Child process is created by fork() in unistd.h library.
->	They have separate memory and process ID.
->	When a child process crashes it will not affect the parent process or other process, this
    is a notable difference between a process and a thread.
->  fork() function returns 0 for child process and child process id for the parent process.
->  getpid() gives current pid and getppid() gives the parent pid.


2. Handling Common Signal
->  Signal.h library is used to handle signal.
->  A signal is a software interrupt that is send to the process.
->  Hardware interrupts are handled by the CPU or OS while signal is handled by process.
->  SIGINT - Signal interrupt
    SIGTERM- Terminate Request
    SIGKILL- kills the process
    SIGSTOP - Pauses the process
    SIGNCONT- Resumes the process
    are few commonly known signals
->  When the signal is passed the perform their default procedure but they can be handled by the 
    handler function. 
->  The signal can be used to ignored, catch signal, terminate the process.
->  eg: signal(SIGINT,handler_function); defined the signal and when SIGINT occurs
    it calls the handler_function.
->  void handler_function(int sig) where sig contains the signal number.

3. Kernel crashes
->  Kernel is the core of the OS.
->  Kernel crash occurs kernel fails execution due to issues like invalid memory
    stack overflow,memory corruption and hardware failure.
->  Kernel failure include Kernel panic, kernel oops, soft and hard lockup, deadlocks etc.
->  When a used space program crashes it has no impact on the kernel, but if a Kernel crashes the
    complete system fails and freezes.
->  Kernel crash can also be caused due to bugged driver and damaged memory.


4. Time complexity

->  Time complexity measures the execution time of a algorithm with respect to the increase input.
->  It uses Big O notation like 
        O(1)    - Constant time 
        O(n)    - Linear time
        O(n^2)  - Quardatic time ->eg: using two loops
        O(log n) - Logrithmic time -> eg: binary search ,every step removes half of the elements 
->  Time complexity is used to test the speed efficiency of an algorithm.

5. Locking mechanism
Mutex,Spinlock

->  In concepts like Threads where shared memory is used we use the lock mechanism.
->  Without Locking mechanism both threads enter the critical session the code that access the 
    shared memory, and get to the race condition. 
->  To avoid this we lock resourse to one thread and then unlock it.

Mutex:
->  Mutual exclusion - Mutex.
->  Only one thread enters the critical session
->  Blocks the waiting thread
->  For long waits.
Spinlock
->  Thread repeatedly checks the lock in a busy-wait loop rather than sleeping when the lock is set.
->  Keeps the waiting thread active.
->  For very short waits.
->  Sleeping is not permitted here.
